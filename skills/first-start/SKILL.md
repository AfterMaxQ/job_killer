# First Start — 首次使用引导

## Purpose

帮助用户理解工具链，并建立当前求职方向画像。求职方向是运行时数据，保存到 Markdown 档案；本 Skill 不修改其它 Skill 的规则、示例或分类体系。

## Core Rules

- 不通过改写 `build-resume`、`greeting-generator`、`hr-communicator`、`interview-question-generator` 或其它 Skill 来适配行业。
- 行业、岗位、候选人阶段、求职重点和偏好统一写入 `个人信息/求职方向/目标方向.md`。
- 已存在求职画像时先读取，只更新用户明确要求修改的字段。
- 不熟悉某个领域时可以说明不确定，但不得把推断写成用户偏好。
- 初始化档案时按 `init-personal-info` 的当前流程执行。

## Workflow

### Step 0：检查当前状态

检查：

1. `个人信息/` 是否存在；
2. `个人信息/求职方向/目标方向.md` 是否存在；
3. 当前档案是否已经足够支持求职 Skill 使用。

根据状态：

| 状态 | 行为 |
|---|---|
| 没有个人档案 | 提供功能介绍或进入“求职画像 + 档案初始化” |
| 有档案、没有求职画像 | 建立 `目标方向.md`，保留其它档案 |
| 已有完整画像 | 展示当前目标摘要，可继续使用、更新方向或更新其它个人信息 |

### Step 1：提供两个入口

用户没有明确指定任务时，提供：

- **A. 了解功能**：快速说明每个 Skill 做什么；
- **B. 初始化 / 更新求职方向**：收集目标岗位和偏好，并按需初始化个人档案。

如果用户已经明确说“换方向”“更新目标岗位”等，直接进入 B，不重复询问入口。

## A. 功能介绍

| Skill | 用途 |
|---|---|
| `init-personal-info` | 建立和维护人类可编辑的 Markdown 候选人档案 |
| `build-resume` | 根据 JD、候选人事实和 Evidence 生成针对性简历与 PDF |
| `greeting-generator` | 生成招聘平台首次触达消息 |
| `hr-communicator` | 辅助处理 HR 后续沟通 |
| `interview-question-generator` | 根据 JD 和候选人经历准备面试问题与回答 |

介绍完后，如果用户尚未建立求职画像，可以建议进入 B；不要强迫执行。

## B. 初始化 / 更新求职画像

### B1：收集必要信息

一次只问一个真正影响画像的问题，优先收集：

1. **目标岗位**：可多个；
2. **偏好行业**：可多个，也可以“不限”；
3. **当前阶段**：例如实习、应届、在职跳槽、转行；
4. **求职重点**：例如希望突出工程交付、研究能力、业务分析、跨领域背景等；
5. **其它偏好**：城市、公司类型、工作语言等用户主动关心的约束。

没有的信息可以留空，不为了填模板追问无关内容。

### B2：写入目标方向.md

文件：

```text
个人信息/求职方向/目标方向.md
```

格式：

```markdown
# 求职方向

## 目标岗位

- 软件工程实习
- 数据分析实习

## 偏好行业

- 企业服务

## 当前阶段

应届生

## 求职重点

希望突出完整交付能力与数据分析实践。

## 其他偏好

- 工作城市：不限
```

示例仅说明结构，实际内容必须来自当前用户。

### B3：已有画像的更新规则

如果 `目标方向.md` 已存在：

1. 先读取当前文件；
2. 明确用户本次要改的字段；
3. 只替换相关字段；
4. 未提及字段保持原值；
5. 如果用户明确要清空某个偏好，才删除对应内容。

例如用户从“软件工程”切换到“商业分析”，只需要更新目标岗位、必要的求职重点和用户明确要求修改的偏好，不修改任何 Skill 文件。

### B4：按需进入个人档案初始化

如果 `个人信息/` 不完整，自动继续执行 `init-personal-info`：

> 求职方向已保存。接下来补全候选人档案，后续简历、沟通和面试 Skill 都会直接读取这些 Markdown。

如果档案已经完整，不重复初始化。

## Cross-domain Check

以下场景必须成立：

```text
当前方向：软件工程
用户请求：改投商业分析
```

正确行为：

```text
读取 个人信息/求职方向/目标方向.md
→ 更新目标岗位 / 求职重点
→ 保留候选人事实档案
→ 不改任何 Skill 文件
```

错误行为：

```text
重写 build-resume 的示例
重写 interview-question-generator 的分类表
把“商业分析”永久写进 Skill 规则
```

## Failure Handling

- 用户目标很宽泛：先保存已确认方向，具体 JD 到来后由对应 Skill 运行时建模。
- 用户同时投多个方向：允许在 `目标岗位` 中保留多个方向，不强迫选唯一岗位。
- 用户只想了解工具链：完成 A 后结束，不强制建档。
- 用户要求修改个人经历而不是求职方向：交给 `init-personal-info` 更新对应 Markdown。

## Validation

完成前确认：

- [ ] 求职方向保存在 `个人信息/求职方向/目标方向.md`；
- [ ] 没有修改任何其它 Skill 文件来做领域适配；
- [ ] 已有画像只修改用户明确要求的字段；
- [ ] 示例内容没有被写入真实用户档案；
- [ ] 当前输出只描述系统当前用法。
