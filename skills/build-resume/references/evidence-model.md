# Candidate Evidence Model

本文件定义候选人档案中的 Evidence（能力证据）语义。Evidence 用于帮助 Agent 判断“某段经历能够证明什么”，不能替代原始事实，也不能用于创造新事实。

## 核心原则

1. **事实优先**：项目、工作、比赛中的原始事实始终是最终依据。
2. **Markdown 主存储**：候选人档案和 Evidence 都使用人类可直接阅读、编辑的 Markdown。
3. **证据与岗位要求分离**：JD 越强调某项能力，不代表候选人对此能力的证据越强。
4. **表达不能超过证据**：弱证据只能支持弱表述，不能因为简历需要而升级为“熟练”“独立负责”“生产级”等更强 Claim。
5. **边界也是证据的一部分**：明确“不能声称什么”可以防止 Agent 在改写时过度推断。

## Evidence Unit

工作、项目、比赛等经历可以在自然语言事实后增加 `# 能力证据`。推荐格式：

```markdown
# 某项目

## 基本信息

- 时间：
- 角色：
- 类型：

## 项目背景

自然语言描述。

## 实际工作

- ...

## 实际成果

- ...

## 使用技术

- ...

# 能力证据

## E1｜能力名称

### 事实

真实发生了什么。

### 可以证明

- 能力 A
- 能力 B

### 证据强度

3 / 5

### 适合支持

- 某类岗位
- 某类职责

### 表达边界

- 不能声称的能力、规模或结果
```

Evidence Unit 中每一项都必须能回到同一经历里的事实，或用户明确确认的信息。

## Evidence Strength

Evidence Strength 仅用于 Agent 做内容取舍和表达强度判断。

| 等级 | 含义 | 典型情况 |
|---:|---|---|
| 0 | 没有证据 | 档案中完全不存在相关事实 |
| 1 | 了解 / 接触 | 阅读、旁观、简单接触，没有可验证实践 |
| 2 | 课程 / 学习 / 简单实验 | 课程作业、自学实验、教程级实践 |
| 3 | 项目中实际使用 | 在真实项目或完整个人项目中使用过 |
| 4 | 独立或核心完成 | 独立负责关键模块，或作为核心贡献者完成 |
| 5 | 真实业务 / 生产环境 / 有明确结果 | 在真实业务中承担责任，并有可验证交付、规模或结果 |

### 评分规则

- 不因为 JD 明确要求而提高 Evidence Strength。
- 不因为某项技术听起来高级而提高 Evidence Strength。
- 没有数据时，不因为缺数字而降低真实的工程交付证据。
- 对同一能力可以有多个 Evidence Unit，Agent 应优先引用最强、最相关且最可验证的证据。
- 用户没有明确说明时，不主动给经历补“生产环境”“核心负责人”等更强语义。

## 虚构示例 A：项目实践，Evidence Strength = 3

```markdown
## E1｜自动化测试

### 事实

在个人课程项目中使用 Playwright 编写 18 条浏览器端回归用例，并在本地运行。

### 可以证明

- 能编写浏览器自动化测试
- 理解基础回归测试流程

### 证据强度

3 / 5

### 适合支持

- 测试开发实习
- 前端工程质量相关职责

### 表达边界

- 不能声称企业级测试平台建设
- 不能声称 CI 中长期稳定运行
- 不能声称覆盖大型生产系统
```

这是完整项目中的实际使用，因此高于“只学习过”，但没有真实业务和生产交付证据。

## 虚构示例 B：真实业务交付，Evidence Strength = 5

```markdown
## E2｜数据自动化

### 事实

在虚构企业“北河零售”实习期间，独立维护每周销售数据清洗任务，覆盖 6 个直营网点；将原本手工合并表格的流程改为 Python 脚本，并连续用于周报生产。

### 可以证明

- 能将重复人工流程转化为自动化任务
- 能维护真实业务数据处理流程
- 具备从需求到交付的独立执行能力

### 证据强度

5 / 5

### 适合支持

- 数据分析
- 业务分析
- 数据运营

### 表达边界

- 不能声称建设企业级数据平台
- 不能声称负责公司数据架构
- 未提供运行时性能数据时不能编造效率提升百分比
```

这里有真实业务、明确责任范围和持续交付状态，因此可以达到 5；没有提供的数字仍然不能补写。

## 证据索引

`个人信息/证据索引.md` 用于快速浏览跨经历的能力证据，例如：

```markdown
# 能力证据索引

## 自动化

- 项目经历/浏览器测试平台.md / E1
- 工作经历/北河零售.md / E2

## 数据分析

- 工作经历/北河零售.md / E3
```

证据索引只负责导航，不是最终事实来源。如果索引和具体经历冲突，以具体经历中的事实为准，并修正索引。

## Agent 使用方法

生成简历时：

1. 先读取与当前 JD 相关的经历事实。
2. 如果存在 Evidence Unit，使用它辅助判断能力和表达边界。
3. 如果没有 Evidence Unit，可以从明确事实中形成 `DERIVED` 判断，但不能增加事实强度。
4. 无证据时标记为 Evidence Strength 0，不写进正式简历。
5. 需要更强 Claim 而证据不足时，在细致模式询问用户；其它模式直接弱化或删除。
