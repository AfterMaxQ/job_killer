# Common Errors and Review Checklist

本文件列出 `build-resume` 常见失败模式。最终验证的完整分工见 `validation-rules.md`。

## Evidence / Claim 错误

| 错误 | 正确做法 |
|---|---|
| JD 很看重某能力，就把候选人弱证据写成强能力 | JD 重要度与 Evidence Strength 分离 |
| “参与”改成“主导”“独立负责” | 保留真实责任范围 |
| 没有性能测试却写“显著优化性能” | 改成事实支持的实现或交付描述 |
| 没有真实数字，为了量化补百分比 | 使用交付状态、规模或定性结果 |
| 团队成果全部写成个人成果 | 只写本人贡献，团队结果注明范围 |
| 课程/自学经历包装成生产经验 | 明确课程、学习或项目实践的真实层级 |
| Claim Audit 中 `UNSUPPORTED` 仍进入最终简历 | 删除该 Claim 或补充真实证据后重新审计 |
| `NEEDS_CONFIRMATION` 未确认就进入全自动结果 | 全自动模式直接弱化或删除 |

## Job Model 错误

| 错误 | 正确做法 |
|---|---|
| 关键词出现一次就判为岗位核心 | 根据职责、频率、工作产出和要求综合判断 |
| JD 所有条目同权 | 形成 P0/P1 与重要度排序 |
| 根据候选人强项反向解释 JD | 先完成 Job Model，再读取 Candidate Evidence |
| 只根据岗位名套职业模板 | 从当前 JD 动态建模 |
| 把 Agent 推断写成招聘方明确要求 | 在 `job-model.md` 明确标记 `[推断]` |

## Positioning / 内容选择错误

| 错误 | 正确做法 |
|---|---|
| 所有经历都想塞进一页 | 根据岗位重要度、Evidence、差异化和篇幅成本选择 |
| 最强证据反而只有一句，弱项目占大量篇幅 | 让 Top Signals 获得最多有效空间 |
| 只用“相关/不相关”决定内容 | 同时考虑证据强度和差异化价值 |
| 简历各模块各写各的，没有统一印象 | 让 Positioning 约束模块排序和内容选择 |

## 写作错误

| 错误 | 正确做法 |
|---|---|
| 每条 Bullet 机械套完整 STAR | STAR 用于内部理解，输出用 Action + Decision + Scope/Result |
| 项目简介强行写虚构“行业痛点” | 只有事实支持时才描述真实问题 |
| “使用 XX 技术”但看不出解决什么 | 写清该技术承担的方案作用 |
| 为了显得高级补缓存、Docker、分布式等未实现技术 | 只写真实使用过的技术和方法 |
| 空泛自评占页面 | 优先使用经历 Evidence；无独特信息时删除自评 |
| 为了填满一页增加重复连接词或背景 | 页面不是必须填满，信息密度优先 |

## 技能 / 核心能力错误

| 错误 | 正确做法 |
|---|---|
| 技能区是一长串名词 | 默认使用“能力主题：关键词；证据信号” |
| 固定“后端/前端/算法/测试”分类所有岗位 | 根据当前 JD + Evidence 动态形成 2–5 个能力簇 |
| 普通 API 调用当作专业技能 | 只有真实任务和工程能力证据时才提升为能力信号 |
| 为了 ATS 把弱证据写成“熟练/精通” | 关键词可以按真实层级出现，表达不能超过 Evidence |
| 证据弱的能力放在第一行核心位置 | 优先展示高 JD 重要度 + 高 Evidence 的能力 |
| 工作经验很强仍塞满技能区 | 使用 Minimal 策略，主要让工作成果证明能力 |

## Markdown / 结构错误

| 错误 | 正确做法 |
|---|---|
| 所有候选人资料堆在一个巨大文件 | 工作、项目、比赛可按经历拆分 Markdown |
| 用 JSON 作为候选人主档案 | Markdown 是 Source of Truth |
| `证据索引.md` 与经历事实冲突还继续用索引 | 以具体经历事实为准，并修正索引 |
| 每份 JD 只生成最终简历，不保存中间决策 | 保存 `job-model.md`、`match-matrix.md`、`positioning.md`、`claim-audit.md` |
| 中间文件名或公司名靠猜 | 使用用户/JD 已提供的可辨识名称，不凭空补充 |

## LaTeX / Rendering 错误

| 错误 | 正确做法 |
|---|---|
| Markdown 中内容正确但 LaTeX 出现未转义字符 | 组装前按 `latex-reference.md` 处理特殊字符 |
| PDF 超页就删掉最核心 Evidence | 先删弱相关内容，再调排版 |
| PDF 不足一页就增加无关文字 | 保留合理留白，不为填满页面降信息质量 |
| 编译失败丢掉分析和 Markdown | 保留任务目录中的所有 Markdown，仅报告构建失败 |
| 编译后遗留 `.aux/.log/.out` | 使用现有 clean/build 流程清理 |

## 最终人工自检

### Evidence

- [ ] 核心 Claim 都能回到候选人事实或用户确认；
- [ ] 没有弱 Evidence 强包装；
- [ ] 所有数字有来源；
- [ ] `UNSUPPORTED` 已从最终 resume 删除；
- [ ] 未确认的 Claim 没有在全自动结果中出现。

### Content

- [ ] 简历能形成清晰 Target Identity；
- [ ] Top Signals 在正文中得到证明；
- [ ] 技能区不是纯名词仓库；
- [ ] Bullet 没有机械 STAR；
- [ ] 没有固定职业 ontology 影响陌生岗位；
- [ ] 页面主要空间给了当前 JD 最有价值的证据。

### Rendering

- [ ] Markdown 与 LaTeX 内容一致；
- [ ] PDF 可正常打开；
- [ ] 无明显溢出、空模块和异常换行；
- [ ] 临时 LaTeX 文件已清理。
