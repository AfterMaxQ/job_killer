# Job Modeling

本文件定义如何把一份 JD 转换成可审查的 `job-model.md`。Job Model 的目标不是做关键词计数，而是回答：**招聘方真正想找什么样的人，以及哪些要求是门槛、核心能力、强信号或加分项。**

## 输入

优先使用：

- 用户提供的完整 JD；
- 用户明确提供的公司、团队、岗位名称；
- `个人信息/求职方向/目标方向.md`，仅用于理解用户投递目标，不用于修改 JD 含义。

信息不足时可以形成部分 Job Model，但必须把推断与 JD 明文要求分开。

## 输出

每个 JD 任务目录生成：

```text
job-model.md
```

推荐结构：

```markdown
# 岗位模型

## 岗位基本信息

- 公司：
- 岗位：
- 团队：
- 职级 / 阶段：
- 主要领域：

## 招聘目标

一句话概括招聘方真正希望招到什么类型的人。

## 核心能力

### P0｜能力名称

- 类型：JD 明确要求 / Agent 推断
- JD 证据：引用或概括对应职责/要求
- 重要度：5 / 5
- 说明：为什么它属于核心能力

### P1｜能力名称

...

## 门槛条件

- 学历：
- 年限 / 实习周期：
- 必备资格：
- 地域 / 工作方式：
- 语言：

## 强信号

- 出现哪些经历会显著提升匹配度

## 加分项

- 有最好、没有也不影响基本资格的能力或经历

## 隐含需求

- [推断] ...

## 岗位核心命题

招聘方实际上在购买什么能力？
```

缺失字段直接省略或写“JD 未说明”，不要凭空补公司、团队、职级等信息。

## 重要度

建议使用 1–5 的语义强度：

| 分值 | 含义 |
|---:|---|
| 5 | 岗位核心，缺失会显著影响竞争力 |
| 4 | 很重要，通常需要较强证据 |
| 3 | 明确要求或高频职责，但不是岗位唯一核心 |
| 2 | 辅助能力 / 常见加分项 |
| 1 | 边缘信息或低权重偏好 |

这不是数学模型，只是帮助 Agent 做相对排序。

## 如何判断 P0 / P1

综合以下信号：

- 是否直接决定岗位主要工作产出；
- 是否在“岗位职责”和“岗位要求”同时出现；
- 是否高频出现并且与工作场景绑定；
- 是否属于不可替代的专业能力，而不仅是工具名；
- 是否明显影响入职后的日常工作。

例如 JD 同时写“负责构建推荐模型”“优化排序指标”“需要机器学习基础”，核心能力更可能是“推荐/排序建模”，而不是某个单独库名。

## 显式要求与推断分离

必须区分：

### JD 明确要求

JD 直接给出的职责、资格、工具、经验或限制。

### Agent 推断

根据岗位职责能够合理推断，但 JD 没有明说的能力。

所有推断必须以 `[推断]` 或等价标记出现在 `job-model.md` 中。

例如：

```markdown
## 隐含需求

- [推断] 该岗位需要较强跨团队沟通，因为职责包含与销售、运营共同定义指标，但 JD 未直接写“沟通能力”。
```

不能把推断伪装成招聘方原话。

## 禁止行为

### 关键词出现一次 ≠ 核心能力

JD 出现一次 `Docker`，不能自动判断“容器化”是 P0。先看它在实际职责中的位置。

### 所有要求不能同权

“熟悉 Git”和“负责核心模型训练”通常不是同一权重。Job Model 必须产生优先级。

### 候选人强项不能反向解释 JD

候选人很擅长某技术，不代表该技术在目标岗位更重要。先完成 Job Model，再读取候选人 Evidence 做匹配。

### 岗位名称不能代替 JD

“数据分析”“AI 工程”“产品运营”等名称只能提供背景，不能直接套固定能力表。必须从当前 JD 动态建模。

### 工具名不能替代能力

优先形成能力表达：

```text
错误：Python / SQL / Tableau
更好：数据处理与分析；可由 Python、SQL、BI 工具作为信号
```

## 信息不足

如果用户只给岗位名称，没有完整 JD：

- 可以基于岗位名称和用户提供的上下文形成低置信度初版；
- 明确标记哪些内容是推断；
- 不得假装知道具体公司的招聘要求；
- 在细致模式可以请求完整 JD；
- 在全自动模式只使用可确认信息继续。

## Validation

生成 Job Model 后确认：

- [ ] 招聘目标能用一句话解释“想招什么人”；
- [ ] 核心能力有明确优先级；
- [ ] 门槛、强信号和加分项没有混在一起；
- [ ] 显式要求和 Agent 推断可区分；
- [ ] 没有因为候选人擅长某项能力而改变 JD 解释；
- [ ] 没有固定套用“后端/前端/算法/测试”等职业 ontology。
